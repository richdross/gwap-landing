# The Leverage Brief Publishing System V1

## Purpose
Turn one high-signal Gwap Gang idea into a repeatable editorial product that can be published as email, web intelligence, and downstream content.

## Canonical Editorial Structure
Every issue uses these six lanes:

1. **Before It's Obvious** — the emerging shift or capability worth noticing early.
2. **The Connection** — how separate technologies, behaviors, or markets combine into leverage.
3. **We Tried It** — a real Gwap Gang test, implementation, or observed result.
4. **The Money Play** — the commercial implication, customer pain, or revenue angle.
5. **Don't Get Cooked** — hype, waste, risk, or implementation traps.
6. **Gwap Guidance** — the practical action or decision framework.

## Subject System
Primary format:
`The Leverage Brief #NNN — <Headline>`

Rules:
- Lead with the idea, not the tool name.
- Prefer tension, consequence, or non-obvious connection.
- Keep the subject readable on mobile.
- Do not use fake urgency or clickbait that the issue does not earn.

## Preview Text System
One sentence that answers: **why should I open this now?**

Example:
`AI access is becoming common. Connected execution is not.`

## Publishing Sequence
1. Select one idea with clear business relevance.
2. Draft the six editorial lanes.
3. Create the web edition under `/brief/<issue-slug>/`.
4. Verify the web URL is live.
5. Create/update the Resend broadcast draft.
6. Check subject, preview, links, sender, reply-to, and unsubscribe.
7. Send a test email to a controlled inbox.
8. Review desktop + mobile rendering.
9. Approve the final broadcast.
10. Send to **The Leverage Brief** segment.
11. Verify delivery metrics.
12. Repurpose the issue into article/video/short/social assets.
13. Review signup, open, click, return-visit, product-click, and purchase signals.
